# 오늘 배운 것

클로드 코드와 함께 마크다운 블로그를 직접 만들어 보았습니다. 프레임워크 없이 순수 HTML, CSS, JavaScript만 사용하니 각 언어가 웹에서 어떤 역할을 담당하는지 훨씬 선명하게 보였습니다.

## HTML — 뼈대

HTML은 페이지의 **구조**를 담당합니다.

- 어떤 내용이 있는지 (`<h1>`, `<p>`, `<article>`)
- 내용들이 어떤 순서로 배치되는지
- 이 요소가 버튼인지, 링크인지, 이미지인지

이번 프로젝트에서 `index.html`은 "포스트 목록이 들어갈 자리"를, `post.html`은 "글 본문이 들어갈 자리"를 정의했습니다. HTML 자체는 아무 내용도 채우지 않고 자리만 잡아두었고, 실제 내용은 JavaScript가 채웠습니다.

> HTML은 설계도다. 어디에 무엇이 들어갈지 미리 정해두는 것.

## CSS — 외형

CSS는 페이지의 **모양**을 담당합니다.

- 색상, 글꼴, 크기, 간격
- 화면 크기에 따라 레이아웃을 바꾸는 반응형 디자인
- 다크 모드처럼 테마를 전환하는 기능

이번에 가장 유용하게 쓴 CSS 기능은 **CSS 변수**였습니다.

```css
:root {
  --color-bg: #ffffff;
  --color-text: #1a1a1a;
}

[data-theme="dark"] {
  --color-bg: #0f0f0f;
  --color-text: #e8e8e8;
}
```

`--color-bg` 같은 변수 하나만 바꾸면 페이지 전체 색이 바뀝니다. 다크 모드를 구현하면서 변수의 힘을 실감했습니다.

## JavaScript — 동작

JavaScript는 페이지가 **동적으로 움직이도록** 만들어 줍니다.

이번 프로젝트에서 JavaScript가 한 일들:

1. **포스트 목록 로드** (`loader.js`) — `posts/index.json`을 읽어 HTML로 변환해 화면에 그림
2. **마크다운 파싱** (`parser.js`) — URL의 `?post=slug`를 읽고 해당 `.md` 파일을 불러와 HTML로 변환
3. **테마 토글** (`theme.js`) — 버튼 클릭 시 다크/라이트 모드 전환, `localStorage`에 저장

HTML이 "버튼이 있다"고 선언하고, CSS가 "버튼은 이렇게 생겼다"고 정의하면, JavaScript는 "버튼을 누르면 이런 일이 일어난다"고 처리합니다.

## 세 언어의 관계

```
HTML   →  무엇이 있는가   (구조)
CSS    →  어떻게 생겼는가 (표현)
JavaScript →  어떻게 동작하는가 (행동)
```

직접 만들어 보기 전까지는 막연하게 알고 있었는데, 빈 `index.html`에서 시작해서 포스트 목록이 화면에 나타나는 순간 이 관계가 눈에 들어왔습니다.
