## 발견 문제와 수정 내역

### ❌ → 수정됨 1. 세로가 낮은 화면에서 점수판이 보드 오른쪽 밖으로 삐져나옴 (MEDIUM)

- 위치: `style.css` `.game-header`, `.title`
- 원인: 제목 글자 크기가 `clamp(40px, 10vw, 72px)`로 **화면 너비** 기준인데, `.app` 너비는 `--board-size`(70vh 상한) 기준. 가로 모드 휴대폰(740x360)이나 높이가 낮은 iframe(600x300)에서는 보드가 좁아지는데 제목은 큰 상태라 헤더가 넘침. 측정값: 740x360에서 점수판 오른쪽 끝 540.7px, 보드 오른쪽 끝 488.5px (52px 초과). 600x300에서는 67px 초과. 다음 단계(Embed)에서 iframe으로 넣으면 바로 드러나는 문제.
- 수정:
  ```css
  .game-header { ... flex-wrap: wrap; ... }
  .title { font-size: clamp(32px, calc(var(--board-size) * 0.16), 72px); }
  ```
- 수정 후: 740x360에서 한 줄로 보드 폭 안에 들어감. 600x300에서는 점수판이 다음 줄로 내려가 넘침 없음. 320/375/768/1280 폭의 결과는 수정 전과 동일 (`@media (max-width: 480px)`의 36px 규칙은 그대로 적용).

### ❌ → 수정됨 2. 두 손가락 터치 후 의도하지 않은 이동 발생 (LOW)

- 위치: `app.js` 터치 핸들러
- 원인: 두 번째 손가락의 `touchstart`는 무시하지만 첫 손가락의 시작 좌표가 남아 있어, 손가락을 뗄 때 `touchend`가 그 좌표로 dx/dy를 계산해 이동이 일어날 수 있었음.
- 수정: `touchActive` 플래그 추가. 한 손가락 `touchstart`에서 true, 멀티 터치가 섞이거나 `touchcancel`이면 false, `touchend`는 true일 때만 처리하고 바로 false로 되돌림. `preventDefault()`는 여전히 `touchmove`에서만 호출하므로 버튼 클릭에는 영향 없음 (spec 5-6 준수).
- 수정 후: 멀티 터치 시나리오에서 이동 없음, 기존 스와이프 4방향과 짧은 스와이프 무시도 그대로 통과.

## 좋은 점

- `game.js`가 DOM/localStorage 없이 순수 함수로만 구성되고 항상 새 배열을 반환해서 테스트하기 쉬움
- 이중 병합 방지가 "원본 tiles 배열을 두 칸씩 건너뛰는" 방식이라 구조적으로 버그가 생기기 어려움
- 승리/게임 오버 판정 순서와 "계속하기" 시 `canMove` 재검사가 spec 3.5와 정확히 일치
- spec의 id/class 이름과 팔레트 값을 그대로 지킴
